# Obsidian 个人知识地图 Skill

帮用户把散落在本机的文件整理成一张 AI 可导航的知识地图（四层结构），并建立"干活 → 扫描入库 → 查图继承上下文"的核心循环。

## 核心概念（先向用户确认的信息）

开工前需要知道：

1. **知识库根目录**：用户的 Obsidian Vault 路径
2. **工作区根目录**：用户实际产出文件存放的路径（可与 Vault 不同）
3. **一级分类**：按"用户在做的事"划分，默认 5~7 个（如：个人项目、课程实践、方法论、个人事务）

## 四层结构规范

```
第 1 层  一级分类       每类一个 MOC（Map of Content）笔记
第 2 层  项目集/主题    每个在做的项目一个节点
第 3 层  知识点         项目下挂技术点/经验点
第 4 层  源文件索引     登记本机真实路径 + 一句话摘要
```

### 节点模板（第 2/3 层通用）

```markdown
---
type: project | knowledge | moc
parent: "[[上级节点]]"
status: active | paused | done
---
# 节点名

## 一句话说明
（这个节点是什么、解决什么问题）

## 知识点
- [[子节点A]]
- [[子节点B]]

## 源文件索引（第 4 层专用）
| 文件 | 本机路径 | 说明 |
|---|---|---|
| sync_board70.ino | D:\path\to\file.ino | ESP-NOW 双板同步固件 |

## 经验沉淀
- （问题 → 判断 → 动手 → 验证 → 总结，按此五段式追加）
```

## 工作流程

### Phase 1：盘点与建模
1. 扫描用户指定的工作区目录（只读，不改动任何文件）
2. 按文件名/目录名/内容摘要做主题聚类，向用户提议 5~7 个一级分类
3. 用户确认后，生成每个分类的 MOC 笔记到 Vault 根目录

### Phase 2：建节点与索引
4. 每个聚出的主题建一个项目节点（第 2 层），挂到对应 MOC 下
5. 每个项目下提炼知识点节点（第 3 层），用五段式写经验
6. 第 4 层登记源文件**真实绝对路径**，供点击定位（提醒用户：私有库才安全）

### Phase 3：建立核心循环
7. 生成 `00-首页.md`：7 张分类卡片 + 数字总览（文件数/节点数）
8. 与用户约定维护纪律：
   - **任务结束重扫**：智能体每完成一个改动文件的任务，自动更新第 4 层索引
   - **单分类 >80 节点即拆分**：提议拆出二级分类
   - **每天只做一件事：给新产出挂链接**

## 硬性规则

- ❌ 未经确认不得移动/重命名/删除用户任何源文件——只建索引
- ❌ 第 4 层路径必须核实存在（找不到的标注 `⚠️ 路径待核实`）
- ❌ 单个 MOC 下的直接子节点不超过 80 个
- ✅ 所有节点用 wiki 链接 `[[ ]]` 互联，保证图谱连通性
- ✅ 涉及隐私的内容（个人事务、账号信息）默认归入"个人事务"分类，并提醒用户该 Vault 只建私有 Git 仓库

## 安全提醒（必须告知用户）

- 如果用户想把知识库发布到 GitHub：必须建议**双仓库方案**——私有库存全量，公开库只放脱敏后的"作品集"
- 公开判断原则：✅ 做了什么/怎么解决/学到什么；❌ 个人事务/账号/本机路径/未完成部分
