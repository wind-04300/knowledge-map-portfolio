# Windows编码与GBK坑

> 第 3 层 · 知识点 ｜ 所属：[[软件与自动化]]

## 结论

- 读写文件一律显式 `encoding='utf-8'`
- 控制台输出中文前先 `chcp 65001`，或直接写文件再读
- 日志写文件比 print 更可靠，出问题能回看

## 踩坑

- 默认 GBK 打开 utf-8 文件直接抛 UnicodeDecodeError
- emoji / 特殊符号在 GBK 控制台会让进程崩掉
- 子进程输出编码不对时，会表现为「程序没输出但也没报错」
