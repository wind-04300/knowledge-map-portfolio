# Obsidian 知识地图方法论（四层结构版）

> 目标：让文件"有地址、有链接、有地图"，让 AI 和人都能快速定位任何知识。

## 一、问题

文件越攒越多：桌面堆满"最终版""最终版2"，做过的项目、下载的资料散落在十几个文件夹。文件还在，但你已经不记得它在哪了；知识和知识之间的联系全在脑子里，时间一长经验就断了线。

## 二、判断

需要的不是更多文件夹，而是一张"地图"。选 Obsidian 的理由：

1. **本地存储**：笔记就是 Markdown 文件，不依赖云服务
2. **双链 + 图谱**：笔记互相链接，自动生成关系网络
3. **插件生态**：免费、可扩展
4. **Markdown 通用格式**：AI 智能体能直接读写（这是关键，见下文）

## 三、动手：四层结构

```
第 1 层  一级分类（5~7 个，按"我在做的事"划分）
第 2 层  项目集 / 主题节点（每个在做的项目一个节点）
第 3 层  知识点节点（项目下挂具体技术点、经验点）
第 4 层  源文件索引（登记本机真实路径，点击可定位打开）
```

### 分类原则

- 按「角色/事情」分类，不按文件类型分类（❌ "文档/图片/脚本"，✅ "个人项目""课程实践""方法论"）
- 单个一级分类超过 **约 80 个节点** 就拆分，否则总览层会退化成新的混乱
- 分类不用一开始就完美，它是随使用"长出来"的

### 双向打通（最关键的一步）

每个第 3 层知识点登记对应源文件的真实路径。这样笔记不是孤岛，而是**入口**：地图上点"某知识点"，能直接打开硬盘里对应的文件。

## 四、验证：三个真实场景

1. **全局总览**：首页 7 张分类卡片，每张标注子项数、节点数
2. **面包屑找回上下文**：`个人项目 → 手写板项目集 → ESP-NOW 收发与配对`，隔一个月回来不迷路
3. **图谱找关联**：图谱视图能看到哪些项目共享同一批方法——旧经验自动复用到新项目，这是文件夹永远做不到的

## 五、与 AI 智能体结合（越用越聪明的核心循环）

```
智能体干活 → 产出文件被扫描入库 → 地图更新
     ↑                                    ↓
     └────── 下一个任务先查地图，继承全部上下文
```

为什么 Obsidian 特别适合当 AI 的"外置大脑"：

| AI 的痛点 | 知识地图怎么解 |
|---|---|
| 新对话失忆 | 地图是"单一事实来源"，多个助手/脚本共用 |
| 上下文装不下、token 贵 | 1386 份文件压缩成 132 个节点，先看目录再取文件 |
| AI 记错跑偏 | 图谱可视化可下钻，断链和过期路径肉眼可见，人能纠错 |

## 六、维护纪律（两条就够）

1. **任务结束让 AI 刷新内容**：AI 改完文件后，让它把新增和变更写进地图（新项目建档、源文件路径更新），否则地图和现实脱节。
   ⚠️ 注意区分：**索引、双链、反向链接、图谱是 Obsidian 自动的**，文件一存它自己重算，不用任何人去"扫描"；AI 负责的是**写内容**，不是刷索引。
2. **每天只做一件事：给新东西挂链接**——图谱是攒出来的，不是设计出来的

## 七、常见坑

- ❌ 追求完美分类才开始 → ✅ 先粗分 5~7 类，边用边调
- ❌ 笔记里只写想法不留源文件路径 → 地图退化成普通笔记
- ❌ 分类无限膨胀不拆分 → 总览层变成新的"散乱桌面"

## 八、云备份（可选，不做也完全能用）

先安心：**Obsidian 本身纯本地**，笔记只存在你硬盘上，不登录、不上传，断网照常用。

想要"电脑坏了笔记也不丢"的保险，才做这一步——把整个库文件夹放进一个 **GitHub 私有仓库**（Private，只有你自己可见）：

| 方式 | 适合 | 一句话流程 |
|---|---|---|
| GitHub Desktop | 怕命令行的人 | `File → Add local repository` 选库文件夹 → 建仓时勾选 Private → 以后写完点 Commit + Push |
| 让 AI 代劳 | 用 WorkBuddy/Claude 的人 | 直接对 AI 说「把我的知识地图备份到 GitHub 私有仓库」 |

两条注意：
1. **一定选 Private**——库里登记着你的项目细节和本机路径，公开 = 全网可见
2. 想展示成果，另建一个公开的"作品集"仓（就像你现在看的这个），和私有备份仓**分开**，这叫分层公开
